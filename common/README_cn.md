FreeACS Fusion - Common
=======================

本项目只是整个产品的一部分。完整信息请访问：
http://www.freeacs.com/

依赖
----
编译时类路径需要 Junit
运行时类路径需要 MySQL 驱动

------------

Git 视图：从 git 仓库导入项目，作为一般项目导入

概述
----
提供 FreeACS 产品中使用的通用功能，是超过 10 年开发的成果。这些功能对其他项目也可能有用。

Common 提供以下功能（括号中指定了等效的开源替代方案 - 如果适用）：

* 数据库连接池（+ 一些跟踪运行状态的方式）（Commons DBCP）
* Log4j 替代品 - 在某些方面更简单/更好（Log4j）
* 任务/线程执行调度器 - 例如：每 24 小时或每分钟运行一次清理作业（Quartz）
* 缓存机制 - 可以指定超时值/类型（EHCache）
* 属性读取器 - 读取属性文件 + 运行时重新加载更改
* 相当快的字母数字排序实现 - 正确地对字母数字字符串进行排序，同时考虑数值和字母顺序

这里还有其他功能，将在后面解释。

数据库连接池
-----------
最初开发这个功能是为了摆脱对 Websphere 数据库连接处理的依赖。如今我不确定这有多相关，Apache commons DBCP 可能是更好的替代方案（我还没有研究过）。主要思想是：

* 提供不依赖应用服务器的连接池
* 丢弃所有涉及 SQLExceptions 的连接 - 所有连接都显式返回给此框架
* 统计连接元数据（成功访问、拒绝访问、同时访问、空闲/使用中的连接）
* 多数据库连接（在同一运行时/JVM 中连接多个不同的数据库）
* 记录所有事件和调试日志
* 被拒绝时重试（几秒钟）- 希望能克服临时的峰值情况
* 可以动态决定是否使用 autocommit=true
* 已测试并在 MySQL 上正常工作。应该适用于任何支持 JDBC 的数据库。
* 可通过属性文件和编码进行配置（您的选择）。

总之，这个系统多年来运行良好。

Log4j 替代品
------------
我使用 Log4j 多年，直到有一天我受够了它。类路径冲突是一个问题，因为 log4j 通常在应用服务器和我的应用程序中都被使用。但主要驱动因素是这个替代品修复的一些其他问题（在我看来）：

* 与 J2EE 服务器中的 log4j 库没有冲突 => 不需要考虑类加载器策略
* 更简单/更好的配置 - 对客户/文档更友好
    - 在一个 appender 配置中指定按大小/时间滚动（例如，每小时滚动一次或大小 > 1M）
    - 指定按时间滚动的备份（用于生产环境中的自动清理）
    - 不需要指定 root-logger
    - 不需要指定继承
    - 自动报告配置错误 -> 易于纠正
* 自动按时间滚动，即使没有日志流量！
* 启动时自动按时间滚动（旧日志将滚动到正确的文件名）
* 保持备份的文件名后缀约定，便于编辑器使用（不再有 .1 后缀！）
* 性能提高多达 300%（某些情况 - 无提高）
* 完全动态重新加载配置 - 一切都可以在运行时更改！
* 支持 Syslog 严重性层次结构（加上 log4j 的 FATAL）

当然，log4j 的某些功能已被牺牲。虽然可以编写新的 Appender 类型（写入数据库而不是文件），但这可能不是这个替代库最擅长的事情。可以打印到文件的语法/选项也更加有限。

总之，我相信这个小系统具有一定的价值，可以用于 FreeACS/Fusion 之外的项目。

调度器
------
我很久以前看过 Quartz Scheduler。我不记得当时为什么没有选择它，也许我认为它太繁琐 - 设置太多。无论如何，调度器确实调度任务/进程/线程执行。它提供以下功能：

- 简单设置（例如：scheduler.registerTask(new Schedule(10000, false, ScheduleType.INTERVAL, new StabilityTask("StabilityLogger")));）
- 在每分钟、每小时、每天的精确时间运行，或按指定间隔运行
- 如果任务未完成，将不会启动同一任务（下一轮）- 将等待下一轮
- 对任务中的异常进行严格控制 - 您将 100% 确定任务已完成或失败
- 如果继承 TaskDefaultImpl，只需要最少的实现
- 可以同时运行许多不同的线程 - 受限于 JVM 生成新线程的速度

总之：相当简单，但易于使用（在我看来）。Quartz 可能更丰富，但到目前为止调度器已经满足了很多需求。

缓存机制
--------
构建此缓存时 EHCache 还不存在。非常简单，但提供基于最后访问时间、创建时间或绝对时间限制的超时。可以存储任何内容，没有限制。可靠的缓存清理。不确定这是否对任何人有兴趣。

属性读取器
----------
我需要一个可以检测属性文件更改的属性读取器。这是通过每 30 秒简单轮询完成的。在 Java 7 中，可以使用 NIO 和 Watch Service API 以更优雅的方式实现。

字母数字（NaturalComparator）排序
---------------------------------
如果您有这样的字符串（想想版本字符串）：

version-1.0.1  
version-1.70.1  
version-1.9.1

使用字母数字排序后应该是这样：

version-1.0.1  
version-1.9.1  
version-1.70.1

这对某些类型的字符串很有意义。已经投入了一些努力来加速比较，几年前在某台笔记本电脑上，每次比较大约需要 9200 纳秒。

其他内容
--------
* FileDatabase：一个超简单的 Java 数据库。
* ObjectGraph：尝试测量单个对象（及其所有引用）占用的字节数 - 不太成功
* Sleep：一种简单的睡眠一段时间的方法，同时仍能检测服务器是否正在关闭
* TimestampMap：如果您想存储具有关联时间戳的字符串，但想自动丢弃那些太旧的字符串。也可以按时间顺序遍历映射，无论它们以什么顺序添加。非常特殊的用例...
* TimeWindow：建模时间窗口（周一-周五：0800-2000），并且始终可以计算每个时间窗口的确切时间戳 - 可以向前/向后滚动时间窗口。
* Validation：一些根据某些规则进行验证的类
* HTML：一个简单的库来指定 HTML。想法是用 Java 编写 HTML，然后在最后"渲染"它。不再需要考虑结束标签，渲染会处理这些。可能有点难以阅读...
